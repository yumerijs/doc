# 插件运行时与生命周期

> 这一章不是“概念总览”，而是把插件在运行阶段真正会发生的事情拆成几部分来讲：上下文、依赖、生命周期、资源清理和副作用管理。

Yumeri 的插件并不是简单“注册一个函数”，而是一个带生命周期的运行时单位。插件在加载、依赖解析、运行、卸载时，都会经过一套框架内置的机制。

## 1. 这章的内容边界

这一章的内容分成 5 个部分：

- [Context 运行时入口](./runtime/context)
- [组件与依赖注入](./runtime/dependency)
- [生命周期与清理](./runtime/lifecycle)
- [定时器、事件与副作用管理](./runtime/effects)

## 2. 一张图理解插件运行时

```text
加载插件
  ↓
解析依赖（depend / optional）
  ↓
创建 Context
  ↓
注册路由 / 组件 / 事件 / Hook
  ↓
插件承担请求处理和扩展逻辑
  ↓
卸载时统一清理副作用和资源
```

这就是 Yumeri 运行时的核心逻辑：插件本身不孤立运行，而是“受到 Context 管理、依赖调度、运行时清理”的整体体系。

## 3. 为什么要拆分成几个小节

如果把所有内容堆在一页里，很容易混淆这几类问题：

- 插件怎么拿到运行时入口？
- 插件怎么拿到不同的共享能力？
- 插件创建的资源怎么清理？
- 定时器和事件监听怎么避免泄漏？
- 插件卸载时为什么必须统一回收资源？

因此，这一章把这些问题拆成几个独立页面来讲，更符合真实开发流程，也更容易维护和扩展。

1. [Context 运行时入口](./runtime/context)
2. [组件与依赖注入](./runtime/dependency)
3. [生命周期与清理](./runtime/lifecycle)

## 5. 关键一句话

插件的真正价值，不在于“能写一个 apply()”，而在于“能在框架中安全地加载、稳定地运行、干净地卸载”。
